# 2026-09-25 : Prise en main de GitHub et répartition des rôles



**Séance :** planifiée · **Durée :** 3 h



## Fait



**Environnement GitHub :** Récupération de nos accès et découverte de l'interface et du fonctionnement de GitHub.
**Documentation continue :** Prise en main du système de documentation sur le repository à travers VSCode (rédaction en Markdown, utilisation du frontmatter, arborescence des fichiers pour le journal de bord).
**Organisation de l'équipe :** Concertation avec Nathan, Archibald, Lylian et Romain pour définir et attribuer les différents rôles (CAO, électronique, programmation, intégration) en fonction des compétences de chacun.


## Pourquoi



**GitHub et documentation :** Utiliser GitHub est indispensable pour centraliser notre travail, versionner nos fichiers et éviter les pertes de données. La documentation continue nous permet de garder une trace de nos choix d'ingénierie, ce qui sera un gain de temps énorme pour la rédaction du rapport technique au semestre 2 et ne pas porposer des idées sur lesquelles nous aurions déjà réfléchi.
**Répartition des rôles :** Définir qui fait quoi dès la deuxième séance permet d'organiser le travail. L'équipe pourra avancer simultanément sur la mécanique et les premiers tests électroniques/code sans se marcher sur les pieds, tout en gardant une vision globale.
